## ステップ1: Supabase（DB）の初期設定 ← まずここから

これをやらないと、アプリがデータを保存する場所がない状態。管理画面（ブラウザ）での作業。

- [ ] Supabaseでプロジェクトを新規作成（リージョンは東京 = ap-northeast-1）
- [ ] SQL Editorで、用意済みのSQLファイルを**順番に**貼って実行
  - `supabase/migrations/0001_init.sql` → `0002_rls.sql` → `0003_storage.sql`
  - ※内容を理解する必要はなく、コピペして実行するだけでOK
- [ ] Authentication（認証）設定
  - メール/パスワードでのログインを有効化（メール確認をON）
  - メール送信サービス「Resend」の接続情報を設定
  - 確認メール・リセットメールの文面を日本語に変更
  - ログイン後のリダイレクト先URLを登録

👉 **おすすめ**: ここはエンジニアと画面共有しながら一緒に進めるのが一番早い。手順自体はSupabaseの管理画面に従うだけなので、難しい操作ではない。

## ステップ3: 実際にアプリを使ってみるテスト ★Shizuruさんの本領

ここが一番大事。ユーザー目線で「ちゃんと使えるか」を一通り体験する。

- [ ] 新規登録 → 確認メールが届く → リンクを押す → ログインできる
- [ ] ログアウト状態でアプリを開く → ログイン画面に飛ぶ
- [ ] ログインしてフィード（投稿一覧）が表示される
- [ ] 投稿を作成 → フィードの先頭に出てくる → リロードしても消えない
- [ ] いいね（ハートなど）を押す → 数字が増える → リロードしても保持される
- [ ] 検索（キーワード・関係性・シーン・価格帯のチップ）がちゃんと絞り込める
- [ ] パスワードを忘れた場合のリセットフロー（メール→新パスワード→ログイン）
- [ ] すでにログイン済みの状態でログイン画面に行くと、自動で元の画面に戻される

👉 **おすすめ**: これは「テストケースをこなす」というより、普通に新規ユーザーになりきって使ってみるのが一番効果的。違和感やエラー表示の日本語が変なところがあれば、それもこのタイミングで気づける。

## おすすめの進め方（まとめ）

1. **ステップ1・2**（Supabase設定・環境変数）はエンジニアと一緒に1〜2時間で片付ける回をつくる
2. その環境ができたら、**ステップ3（使ってみるテスト）はShizuruさん主導**でじっくりやる ← ここが一番価値が出るところ

4. 修正後、**お試し公開でもう一度ステップ3**
5. 問題なければ本番公開 → 公開後にもう一度軽く触って確認

つまり「設定は人に任せて、体験のチェックは自分が主役」という分担にすると、無理なく進められそうです。
